# 交互设计：Token 优化 · 精简阶段基础上下文与重复读取

依据：`spec.md`（S1–S9、R1–R9、E1–E12、AC-1–AC-14）。本文只定义操作者看到什么、在哪里看到、各状态下怎么变化；参数组合、会话读取、计数算法留给技术方案。界面只改 `studio/`（Tauri），GPUI `desktop/` 不改。

## 0. 不改的部分

- 阶段流程、阶段模板、验收与送回、自动运行抽屉的布局不变。
- 阶段配置（CLI / 模型 / 沙箱 / 预算）的输入方式不变；本次只在旁边加只读说明。
- 「Token 消耗」页现有卡片（总计、缓存占比、费用、账号额度、项目默认阶段预算、按阶段 / 模型 / 事项 / 天、消耗最多的执行）保留原样和顺序，新增内容插在明确位置（§3）。
- R1 最小启动本身没有开关，操作者不需要做任何选择；界面只**展示**它的效果（§3.4、§4.3）。
- R5 读取约定只进提示词，不在界面出现。

## 1. 用户路径

**P1 运行一个阶段（S1、S5）**
1. 操作者在事项页选中当前阶段。右侧「此阶段配置」卡下方新增一行「会话」预告（§4.1）：「将复用「产品需求」的会话」或「将开新会话 · 原因」。
2. 点「运行」。轮次标题的元信息行（`turn-meta`）多一段会话标签（§4.2）。
3. 执行结束：轮次底部的用量行不变；展开「用量分析」时顶部多一行「启动配置」（§4.3），显示 MCP / skills / 插件数量和首轮上下文。

**P2 相邻阶段复用（S3、AC-6）**
1. 产品需求通过后，交互设计成为当前阶段。阶段条上交互设计的说明文字（`step-caption`）在 CLI · 模型后面追加「↻ 复用」（§4.4）。
2. 运行后，会话视图里这一轮的用户气泡下方显示「复用自：产品需求的会话」，可点击跳到产品需求阶段最新通过的那一轮。
3. 本阶段只显示本阶段的轮次和本阶段窗口内的用量；不把前序阶段的对话合并进来。

**P3 会话过大改新会话（S4、E4、E5）**
1. 操作者在已完成的阶段里「继续对话」，或前序修改后「复核」，或下一阶段本可复用。
2. 平台判断上次调用上下文已超过阈值 → 轮次标签显示「新会话 · 上下文超过阈值（182K > 150K）」，旁边小字「已带上一轮结果和交接摘要」。
3. 不弹确认框，不打断；自动运行（S9）时行为一致。

**P4 看优化效果（S8、AC-11）**
1. 打开「Token 消耗」页。在三张汇总卡下方、「项目默认阶段预算」上方出现「优化前后对比」卡（§3.1）。
2. 按阶段逐行对比首轮上下文、平均调用次数、每次执行平均总量和变化百分比；可切到按 CLI · 模型。
3. 在「消耗最多的执行」里，每行带「最小启动」或「优化前」小标签，展开后看启动配置（§3.4）。

**P5 预算（R8、R9）**
1. 在阶段预算输入框里，没有自己的预算时，placeholder 优先显示建议值（§4.5）。
2. Codex 阶段执行中，若无会话日志，执行状态行显示「只在结束时计数」（§4.6）。
3. ZCode 阶段被预算停下：决策区按 R7 结论显示「追加预算并继续」或「只能重跑」+ 原因（§4.7）。

**P6 设置阈值（R2）**：在「Token 消耗」页「项目默认阶段预算」卡里，同一卡片新增「续接上限」输入（§3.2）。

## 2. 统一文本

### 2.1 会话标签（阶段条、轮次、evidence 解释共用一个格式函数）

| 情形 | evidence 字段 | 显示 |
|---|---|---|
| 复用相邻阶段 | `reused_session.stage` | 复用自「<阶段名>」的会话 |
| 本阶段继续对话 / 复核（原有行为） | resume 本阶段会话 | 继续本阶段会话（只在轮次上显示，阶段条不显示） |
| 新会话：第一个运行的阶段 / 前序无会话 | `fresh_session_reason: "no_prior"` | 新会话 |
| 上下文超过阈值 | `context_over_threshold` + 当时值 | 新会话 · 上下文超过阈值（182K > 150K） |
| CLI 不同 | `client_differs` | 新会话 · CLI 不同（前序 Codex） |
| 模型不同 | `model_differs` | 新会话 · 模型不同（前序 opus） |
| 权限 / 沙箱 / 工具集不同（E8） | `permission_differs` | 新会话 · 权限不同（前序只读） |
| 工作目录不同 | `workdir_differs` | 新会话 · 工作目录不同 |
| 前序会话不可续接（E4，文件丢失 / resume 失败） | `session_unavailable` | 新会话 · 前序会话无法续接 |
| 前序被预算停下（E9） | `prior_budget_stopped` | 新会话 · 前序阶段被预算停下 |
| 同一会话正在被另一次执行使用（E10） | `session_busy` | 新会话 · 前序会话正在使用 |
| 中间隔了其他 CLI 的阶段（E6） | `chain_broken` | 新会话 · 中间阶段用了其他 CLI |
| ZCode / 自定义 CLI | `client_not_reusable` | 不显示标签（这些 CLI 本来就不复用，避免噪音） |
| 旧记录（无字段） | — | 不显示标签 |

- 括号里的「前序 X」取比较对象那个阶段的值；模型为空写「默认模型」。
- 超阈值、不可续接这几类改新会话的情况，标签后再加灰色 caption「已带上一轮结果和交接摘要」。
- 复用来源被跳过时（E6），「复用自」写**实际被复用的那个阶段**，不写被跳过的阶段。

### 2.2 启动配置文本

```
最小启动 · MCP 0 · skills 0 · 插件 0 · 首轮 9.8K
```

- 有不可关闭的内置项时数字照实写，hover 列出名称（AC-1）。
- E3 某参数不被支持：琥珀色「部分最小化 · 未能关闭：<参数>」，hover 显示 Claude Code 版本。
- 旧记录 / 非 Claude：「优化前」（旧 Claude 记录）或不显示（Codex / ZCode 无 init 统计时）。
- 没有 init 或用量事件（E12）：「首轮 —」，并在对比卡中不计入。

## 3. 「Token 消耗」页（`Usage.tsx`）

### 3.1 新卡片「优化前后对比」

**位置**：`usage-cards` 之后、`usage-budget` 之前，占整行。

**布局**：

```
优化前后对比                          [按阶段 | 按 CLI · 模型]
以执行记录里是否带「最小启动」标记分界，旧记录都算优化前。
┌──────────┬───────────────┬─────────────┬──────────────────┬────────┐
│ 阶段      │ 首轮上下文(中位) │ 平均调用次数   │ 每次执行平均总量     │ 变化    │
│ 产品需求   │ 256K → 10K     │ 38 → 21     │ 6.1M → 1.2M      │ −80%   │
│ 开发实现   │ 248K → 12K     │ 120 → 96    │ 18M → 6.4M       │ −64%   │
│ 测试验证   │ 251K → —       │ 44 → —      │ 7.9M → —         │ 暂无优化后 │
└──────────┴───────────────┴─────────────┴──────────────────┴────────┘
```

- 每格「前 → 后」，hover 显示两边的执行次数（「优化前 12 次 · 优化后 3 次」）。
- 「变化」按每次执行平均总量计算：下降为成功色「−80%」，上升为警示色「+12%」；|变化| < 5% 显示灰色「持平」。
- 「按 CLI · 模型」切换后，行变为「Claude · 默认模型」「Codex · gpt-5」等，列不变。
- 排序：按优化前平均总量降序（与「按阶段」卡一致：最贵的在上）。
- 优化后样本 < 3 次时，变化列后加灰色「样本少」，不改数值。
- 行可点击：展开该阶段最近 5 次执行的列表（复用 `usage-runs` 行样式），便于对照。

**状态**：

| 状态 | 显示 |
|---|---|
| 加载中 | 与整页共用「正在汇总各次执行的用量…」，卡片不单独占位 |
| 失败 | 与整页共用 `inline-error` |
| 没有任何执行 | 不显示本卡 |
| 只有优化前记录 | 卡片显示，表格「后」列全为「—」，变化列「暂无优化后」；卡片说明改为「升级后的第一次执行完成后开始对比。」 |
| 只有优化后记录（新项目） | 不显示本卡（无可对比），其他卡照常 |
| 某行优化前或后全被 E12 排除 | 对应格「—」，hover「被中断的执行不计入」 |

### 3.2 「项目默认阶段预算」卡增加续接上限

在现有卡片同一行后面追加：

```
项目默认阶段预算 [ 不限   ]   续接上限 [ 150K ]
没有单独设置预算的阶段用这个值；……
续接时上次调用的上下文超过这个值，就改开新会话并带上交接摘要，避免越聊越贵。留空用默认 150K。
```

- 输入复用 `BudgetField`（支持 2M / 500k），placeholder「默认 150K」。
- 保存后 toast「续接上限 120K」/「续接上限恢复默认 150K」。
- 非法值（< 20K）：输入框标红，title「至少 20K，否则几乎每次都会开新会话」。具体下限由技术方案定，交互上只要求有下限提示。
- 位置是否为项目级由技术方案「待确认 3」决定；若最终为全局设置，文案改为「所有项目的续接上限」，位置不变。

### 3.3 Codex 计数修正标记（E11）

- 「消耗最多的执行」行：历史 Codex 记录按新规则重算过的不加标记；无法重算的在数字后加琥珀色 tag「计数可能偏高」，hover「缺少会话日志，无法按本轮窗口重算，保留原始数值」。
- 「按阶段」「按事项」等汇总数字照常相加，表头 hover 补一句「含 N 次计数可能偏高的 Codex 执行」（N > 0 时才出现）。

### 3.4 「消耗最多的执行」行

- 元信息行末尾追加启动标签：Claude 新记录「最小启动」，旧 Claude 记录「优化前」，其他不显示。
- 复用会话的执行再加「↻ 复用自 <阶段名>」。
- 展开后的 `UsageBreakdown` 见 §4.3。

## 4. 事项页

### 4.1 「此阶段配置」卡：会话预告（`StageConfig.tsx`）

当前阶段、还没有运行中的轮次时，在配置摘要下方加一行只读文字：

| 情形 | 文本 |
|---|---|
| 可复用 | ↻ 将复用「产品需求」的会话 · 只发本阶段职责和说明 |
| 不可复用 | 将开新会话 · 模型不同（前序 opus） |
| 前序会话超阈值 | 将开新会话 · 前序会话上下文 182K 超过上限 150K |
| 第一个阶段 / ZCode / 自定义 CLI | 不显示 |

- 操作者改 CLI / 模型 / 沙箱后预告立即刷新（这就是「怎样才能复用」的提示，不另加说明）。
- 预告是预测：真正运行时若条件变化（E4、E10），以轮次上的标签为准，不报错。
- 如技术方案判断实时预告成本过高，可退化为只在运行后显示（§4.2），本行省略；不影响验收。

### 4.2 轮次元信息（`Transcript.tsx` → `Turn` 的 `turn-meta`）

现状：`[继续对话] [T2 子任务] Claude · 默认模型 · 10:42`

改为：`[继续对话] [T2 子任务] Claude · 默认模型 · <会话标签> · 10:42`

- 会话标签按 §2.1；「复用自「产品需求」的会话」中的阶段名是链接，点击切到该阶段并滚动到被复用的那一轮（`data-attempt`）。
- 新会话的原因用灰色；超阈值类后跟 caption「已带上一轮结果和交接摘要」。
- 运行中（`initializing`）就显示标签：启动时已经决定，不等结束。
- 用户气泡内容：复用时显示的是实际发出的短提示（职责 + 说明 + 档案位置），这样操作者能看到确实没重发前序全文。

### 4.3 用量分析（`Budget.tsx` → `UsageBreakdown`）

在 `ub-head` 下方、`TokenBar` 上方加一行「启动配置」（§2.2）。

- 复用的执行：这一行写「复用会话 · 首轮已缓存 xxK」，并说明「本轮只计本阶段窗口内的 N 次调用」（AC-8）。
- 已有的「每次调用的上下文」火花图不变；超阈值改新会话的执行，第一根柱子 hover 补「新会话 + 交接摘要」。
- 加载 / 失败 / 无记录沿用现有三种状态。

### 4.4 阶段条（`WorkPage.tsx` → `Pipeline`）

- `step-caption` 现为「Claude · 默认模型」。阶段**已运行且最新通过的一轮**是复用来的，追加「 · ↻ 复用」；改新会话的原因**不**放在阶段条（太长），只在 title（hover）里写完整标签。
- 尚未运行的阶段不显示（避免和 §4.1 预告不一致时造成误导）。
- 被跳过的阶段保持「已跳过」。

### 4.5 预算建议值（R9，`StageBudget` / 自动运行抽屉）

| 情形 | 阶段预算输入框 placeholder | 输入框下方 hint |
|---|---|---|
| 有优化后同阶段历史 | 建议 1.8M | 优化后 5 次执行中位数 1.2M × 1.5；点「采用」填入（`link-btn`） |
| 无优化后历史，有项目默认 | 默认 2M（现状） | 无 |
| 都没有 | 不限（现状） | 无 |

- 建议值只填 placeholder，不自动保存；点「采用」等同于输入后回车，toast「已设为建议值 1.8M」。
- 已设置自己的预算时不显示建议。
- 自动运行抽屉里的紧凑版预算行只显示 placeholder，不显示 hint 和「采用」。

### 4.6 Codex 实时计数说明（R8，`TurnStatus` live 分支）

- 执行中、client 为 Codex、找不到会话日志：在耗时后加琥珀色「只在结束时计数，预算无法中途生效」，替代 `BudgetMeter`（因为数值始终为 0，进度条会误导）。
- 找到会话日志：沿用现有 `BudgetMeter`。
- 结束后不再显示该说明，用量行照常。

### 4.7 ZCode 被预算停下（R7，`DecisionPanel`）

| R7 结论 | 决策区 |
|---|---|
| 支持继续原任务 | 与 Claude / Codex 相同：`ExtendBudget`「追加预算并继续」 |
| 不支持 | 隐藏「继续时要说的话」输入框，按钮改为「追加预算并重跑」；上方灰字「ZCode 不支持在原任务上继续，会按原说明重新运行这一阶段」 |

## 5. 自动运行（S9、AC-7）

- 规则与手动完全一致，不新增确认步骤。
- 自动运行抽屉的阶段列表每行在 CLI · 模型后显示与 §4.4 相同的「↻ 复用」（已运行）或 §4.1 的预告短语（未运行，仅原因关键字，如「新会话 · 权限不同」）。
- 自动运行中途发生「超阈值改新会话」不算异常，不停下、不 toast；只在轮次标签上体现。

## 8. 留给技术方案

1. 会话预告（§4.1）能否在不启动 CLI 的前提下廉价算出；不能则省略。
2. 续接上限是项目级还是全局（影响 §3.2 文案），以及最小值。
3. evidence 字段的最终命名（§6）。
4. R7 ZCode 是否支持继续（决定 §4.7 走哪一行）。

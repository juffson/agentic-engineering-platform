# PRD：Token 优化 · 精简阶段基础上下文与重复读取

## 背景

「Token 消耗」页分析了本项目 53 次执行：共 125M tokens，其中 93% 是缓存读取，Claude 按标价约 $44。缓存读取多，是因为每次模型调用都把整段上下文重新读一遍，所以**基础上下文的大小 × 调用次数**决定了总量。

代码现状（已核对）：
- `src/workflow_stage.rs::invoke` 启动 Claude 时只传 `-p --output-format stream-json --verbose --permission-mode … --tools …`，没有限制 MCP、用户设置、skills、插件或自动记忆。`--tools` 只能过滤内置工具，所以 init 里仍有 32 个 MCP 服务器（343 个工具）、81 个 skills 和 9 个插件，首轮约 256K。
- 同样的问题也出现在其他 Claude 调用：`src/memory_tidy.rs::ask`（整理记忆、CLI 起草）、`src/agent.rs`（独立审查，已有 `--tools ""` 和 `--no-session-persistence`）。
- 只要有前序会话，续接就一律 resume（`workflow_stage.rs`：`let resume = prior…session`），不看会话已有多大。
- Codex 用量：`src/usage.rs::codex` 把 stdout 里每个 `turn.completed.usage` 加起来。resume 时这个值可能是会话累计值（有一次复核只有 1 次调用，却记了 7.3M）。
- 本机 Claude Code 版本是 2.1.331，支持 `--strict-mcp-config`、`--mcp-config`、`--setting-sources user,project,local`、`--disable-slash-commands`、`--bare`、`--safe-mode`、`--session-id`、`-r/--resume`。
- 已实测：同一个写文件任务加 `--strict-mcp-config` 后，首轮约 10K。

目标：在**阶段产出质量和流程不变**的前提下，大幅降低每个阶段的 token 消耗，并能在「Token 消耗」页看到优化前后的对比。

## 用户场景

- **S1 最小启动**：用户运行任意 Claude 阶段（产品需求 / 交互设计 / 技术方案 / 开发实现 / 测试验证 / 复核等）。子进程不加载 MCP、用户级设置、skills、插件或自动记忆；只保留项目设置和项目 CLAUDE.md。阶段照常读写代码和规格。
- **S2 其他 Claude 调用**：「整理记忆」「CLI 起草新事项」（`memory_tidy::ask`）和独立审查同样以最小配置启动。
- **S3 相邻阶段复用会话**：产品需求、交互设计、技术方案选了相同的 CLI 和模型（如都是 Claude 默认模型）。产品需求通过后，交互设计在产品需求的会话里继续，只发本阶段的职责和说明，不再重发基础上下文和前序产出。阶段条和会话视图标明「复用自：产品需求的会话」。
- **S4 会话过大改新会话**：被续接的会话（含 S3 复用和送回后的继续对话 / 复核）上次调用的上下文已超过阈值（默认 150K）。平台不 resume，改为新会话，并带上一轮结果和交接摘要。界面说明「上下文超过阈值，已改为新会话 + 交接摘要」。
- **S5 不能复用的情形**：相邻阶段的 CLI、模型、权限模式、沙箱或工作目录有任何不同时，开新会话。界面说明原因。
- **S6 读取约定**：阶段提示词要求先用 `rg` / `codegraph` 定位，再按行范围读取；不 `cat` 整个大文件；命令输出过长时用 `head` / `tail` 截断，或写到文件后按需读取。
- **S7 Codex 计数准确**：Codex 的继续对话 / 复核记的用量，与 `~/.codex/sessions` 会话日志中该时间窗口内的调用一致。
- **S8 前后对比**：用户在「Token 消耗」页按阶段看优化前后的首轮上下文、平均调用次数、每阶段平均总量和变化百分比。
- **S9 自动运行**：「自动运行」整条流程时，S1、S3–S6 的规则同样生效，不需要人工确认。

## 范围

### 做
1. **R1 Claude 最小启动**（`workflow_stage.rs` 拼参数处，以及 `memory_tidy::ask`、`agent.rs` 审查）：
   - 加 `--strict-mcp-config`，且不传 `--mcp-config`。
   - `--setting-sources project,local`，不读用户级设置（用户级设置里的 hooks、插件启用、权限也不再生效）。
   - `--disable-slash-commands`，关闭 skills 和命令。
   - 关闭自动记忆和用户级 CLAUDE.md。实现前先核实可用手段（如 `--bare` 会把认证限制为 API key，不能直接用；`--safe-mode` 会同时关闭项目 CLAUDE.md，也要核实）。核实结果和最终选用的参数组合写进技术方案。
   - 选定的参数组合集中在一处，所有 Claude 调用共用。
   - 用 init 事件里的 `tools`、`mcp_servers`、`skills`、`plugins` 数量和首轮上下文验证效果，并写进执行证据（evidence.json）。
2. **R2 续接阈值**：在续接前读取被续接会话最后一次调用的上下文（input + 缓存读 + 缓存写）。超过阈值（默认 150K，可在项目设置调整）就不 resume，改为新会话，提示词包含：本阶段职责和说明、上一轮 result.txt、AEP-HANDOFF 交接摘要和回执位置。适用于 Claude 和 Codex。
3. **R3 相邻阶段复用会话**：
   - 复用条件（全部满足）：CLI 相同；模型相同（都为空，即都用默认，也算相同）；权限模式 / 沙箱 / `--tools` 集合相同；工作目录相同；前一阶段已通过且有可续接的会话；会话上下文未超过 R2 阈值。不满足任一条件时开新会话。
   - 只要前一个阶段是复用来的，连续几个阶段就沿着同一会话链继续，直到任一条件不满足。
   - 续接时只发新阶段的职责、说明和本次档案位置，不重发前序产出全文。
   - 每个阶段仍有独立的执行目录、result.txt、evidence.json、执行回执、交接和封存。evidence 记录 `reused_session: {stage, run, session}` 和未复用时的原因。
   - 用量只记本阶段窗口内的调用，不把前序阶段的调用算进来。
   - 阶段条和会话视图显示「复用自 <阶段名>」或「新会话（原因）」。
   - 只有 Codex 和 Claude 可以复用；ZCode 和自定义 CLI 不复用。
4. **R4 Codex resume 计数**：核实 `exec resume` 时 `turn.completed.usage` 是本轮增量还是会话累计。如果是累计，改成取差值，或以会话日志中本次时间窗口内的调用为准。用一个包含 resume 的样例写回归测试。
5. **R5 读取约定**：在阶段提示词公共部分加入 S6 的约定，作为说明加入，不改变阶段模板和流程。
6. **R6 Token 消耗页对比**：按阶段（及 CLI / 模型）对比「优化前 / 优化后」的首轮上下文（中位数）、平均调用次数、每次执行平均总量和变化百分比。分界点是每次执行的 evidence 里是否带最小启动标记（R1），旧记录自动归为「优化前」。

### 顺带
7. **R7 ZCode 被预算停下后续接**：先核实 ZCode 是否支持继续原任务。支持就提供「继续」；不支持就保持只能重跑，并在界面说明原因。
8. **R8 Codex 实时计数说明**：找不到 `~/.codex/sessions` 下的会话日志时，界面说明「本次只在结束时计数，预算无法中途生效」。
9. **R9 预算建议值**：按该阶段优化后历史执行的中位数 × 1.5 给出建议值。没有优化后历史时不给建议，沿用现有默认值。

### 不做
- 更换模型，改变阶段流程、阶段模板和验收方式。
- 改变 ZCode 和自定义 CLI 的启动方式（R7、R8 的说明除外）。
- 推送、合并、发布。

## 边界情况

- **E1** 用户在项目里有 `.mcp.json`（项目级 MCP）：最小启动同样不加载（`--strict-mcp-config` 而且不给 `--mcp-config`）。阶段需要的能力只靠内置工具和 Bash（包括 `codegraph` CLI）。
- **E2** 用户级设置里有阶段依赖的权限放行：最小启动后不再生效，由平台已有的 `--permission-mode` / `--allowedTools` 兜底。如果有阶段因此失败，要在技术方案里列出需要补的参数。
- **E3** Claude Code 版本过旧，不支持某个参数：先探测版本或 `--help`，不支持的参数不传，并在 evidence 里写明「未能最小化：<参数>」。阶段照常运行，不报错。
- **E4** 被续接的会话文件已被删除或无法 resume：退回新会话 + 交接摘要，与 E5 相同，不让阶段失败。
- **E5** 会话超过阈值时改新会话：结论仍需满足原阶段格式（AEP-HANDOFF、AEP: PASS 等），交接摘要里要有前序结论、证据位置和未决事项。
- **E6** 前一阶段是 AEP-SKIP 跳过的：被跳过的阶段没有会话，复用判断跳过它，与再前一个实际运行的阶段比较；中间隔了其他 CLI 的阶段时不复用。
- **E7** 前一阶段被送回后重跑：复用最新一次通过的执行的会话，而不是被送回的那一次。
- **E8** 相同模型但权限不同（如技术方案只读、开发实现可写）：不复用，原因写「权限不同」。
- **E9** 阶段被预算停下：被停的会话不作为后续阶段的复用来源。
- **E10** 同一会话被两个阶段并发续接（如重试时前一次仍在运行）：后来者开新会话，不并发写同一会话。
- **E11** Codex resume 计数修正后，历史记录的累计值按新规则重算；无法重算（缺会话日志）的标记为「计数可能偏高」，不改原始数据。
- **E12** 首轮上下文没有 init 或用量事件（被中断）：对比时不计入该次执行。

## 验收标准

- **AC-1** Claude 阶段最小启动：一次新会话的 Claude 阶段，init 事件中 `mcp_servers` 为空、MCP 工具数为 0、skills 为 0、plugins 为 0（或只剩不可关闭的内置项，在 evidence 中列出），首轮上下文 < 40K；evidence.json 记录这些数量和首轮上下文。
- **AC-2** `memory_tidy::ask` 和独立审查的 Claude 调用使用同一组最小启动参数（单元测试校验拼出的参数）。
- **AC-3** 同类 Claude 阶段（同一阶段、同一模型）优化后的平均总量比优化前下降 60% 以上，在「Token 消耗」页的对比中可以看到。
- **AC-4** 续接上限：被续接的会话最后一次调用上下文 > 阈值时，不传 `--resume` / `exec resume`，改为新会话，提示词含上一轮结果和交接摘要；evidence 记录 `fresh_session_reason: "context_over_threshold"` 和当时的上下文值。≤ 阈值时照常 resume。两个分支都有测试。
- **AC-5** 改为新会话后，阶段仍输出合规的 AEP-HANDOFF（门禁阶段还要有 AEP: PASS / 失败结论），回执、交接、封存流程照常通过。
- **AC-6** 相邻阶段复用：产品需求 → 交互设计 → 技术方案用相同的 Claude 模型和权限时，后两个阶段 resume 前一阶段的会话，提示词不含前序产出全文；每个阶段各有独立的 result.txt、evidence.json 和回执；evidence 记录 `reused_session`；阶段条和会话视图显示「复用自 …」。
- **AC-7** 不复用：CLI、模型、权限 / 沙箱或工作目录任一不同（E6–E10）时开新会话，界面和 evidence 写明原因。自动运行时行为相同。
- **AC-8** 复用时每阶段的用量只计本阶段窗口内的调用，同一会话的多个阶段用量之和等于会话日志的总调用量。
- **AC-9** Codex resume 计数：用包含 resume 的 stdout 样例和会话日志测试，阶段记录的用量与会话日志中该时间窗口内的调用之和一致（误差 0）。
- **AC-10** 阶段提示词含读取约定（S6），有测试断言提示词中出现该段。
- **AC-11** 「Token 消耗」页按阶段显示优化前 / 后的首轮上下文中位数、平均调用次数、平均总量和变化百分比；旧记录归入「优化前」。
- **AC-12** 找不到 Codex 会话日志时，界面显示「只在结束时计数」的说明（R8）；预算建议值 = 优化后同阶段历史中位数 × 1.5，没有优化后历史时不显示建议（R9）。
- **AC-13** R7 有明确结论：支持时可以在原 ZCode 任务上继续并有测试；不支持时界面说明原因。
- **AC-14** 回归：`cargo test --locked` 全部通过，Studio API 测试和 UI 测试全部通过；交接、验收回执、封存流程的现有测试不受影响。

## 待技术方案确认

1. 关闭自动记忆和用户级 CLAUDE.md 的可靠参数（环境变量 / settings 键 / `--safe-mode` 对项目 CLAUDE.md 的影响）。
2. Codex `turn.completed` 在 resume 下的语义（R4），以及 Codex 是否有与 `--strict-mcp-config` 等价的手段（它的首轮已经约 20K，不是本次重点）。
3. 续接阈值的配置位置（项目设置或全局）和默认值 150K 是否合适。
4. 复用会话时 Claude `--add-dir`（前序回执目录）是否要随阶段变化，以及续接时能否追加。

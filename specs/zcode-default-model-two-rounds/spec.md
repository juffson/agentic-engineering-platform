# PRD：ZCode 项目默认模型 · 两轮验证

## 背景

「项目设置 → ZCode 项目默认模型」已实现（见 `Project::zcode_default` / `set_zcode_default`、`aep project zcode-default`、Studio `zcode.rs`、`relay_page.rs`）。
本需求不新增功能、不改动已有实现，只规定**两轮接力**中该默认值如何生效，并给出可复验的验收标准。

> 说明：本次请求的 `brief` 为空，范围按事项标题和 README「两轮接力」一节推断。若原意是别的验证对象，请在确认本 PRD 时指出。

## 目标

项目保存一个 ZCode 默认模型后，一次两轮接力中的每一轮（实现 → 审查）都能确定地用上它，可按轮覆盖，并且每轮实际使用的模型都留在证据里，操作者无需打开日志就能核对。

## 用户场景

- **S1 保存默认**：在项目设置选择本机 provider、模型和推理档位，保存为项目默认；也可用 CLI `aep project zcode-default --model <值>`。
- **S2 第一轮沿用默认**：新建两轮接力，ZCode 作为实现端或审查端时，模型栏预填项目默认。
- **S3 第二轮沿用默认**：第一轮通过后进入第二轮，未手动改过时再次预填项目默认。
- **S4 按轮覆盖**：某一轮改选其他模型或点「使用客户端默认」，只影响该轮。
- **S5 重试保留**：重试某一轮沿用该轮已用的配置，而不是回到项目默认。
- **S6 回看证据**：重开 Studio 后，两轮时间线和执行证据显示各自实际用的模型。

## 范围

**包括**
- 两轮接力中项目默认的预填、覆盖、重试和持久化规则。
- ZCode 同时作为实现端和审查端的情形（共用一个模型配置，各自独立会话）。
- 证据中的模型记录。
- 现有 CLI 与 Studio 两个入口的一致性。

**不包括**
- 新增或修改模型目录、provider、推理档位的发现逻辑。
- 非 ZCode 客户端（Codex、Claude、自定义 CLI）的模型选择。
- 工作流阶段计划（`stage_plan`）里已固定的每轮配置：它优先于项目默认，保持现状。
- push、合并、发布。

## 边界情况

- **E1** 项目没有 ZCode 默认（或已清除）：模型栏为空，表示使用客户端当前配置，不传 `--zcode-model`。
- **E2** 保存的默认在本机已不可用（模型被移除）：保存时校验「本机 ZCode 未提供此模型或档位」；已保存的值在后来失效时，该轮显示警告，不静默回退。
- **E3** 只带档位的值（如 `@high`）：按现有 `effective_selection` 规则归一化后再比较、再记录。
- **E4** 第一轮覆盖不改变项目默认，也不改变第二轮的预填。
- **E5** 两个项目各有不同默认时，互不影响。
- **E6** 旧接力记录没有 `zcode_model` 字段：按空值处理，沿用原有行为。
- **E7** ZCode 审查端有独立的审查模型（`reviewer_model`）时，审查按该值，不受实现端模型影响。

## 功能需求

- **FR-1** 新建接力时，ZCode 模型栏预填项目默认；无默认则为空。
- **FR-2** 第一轮通过后、尚无第二轮记录时，第二轮预填项目默认（阶段计划接力除外，见范围）。
- **FR-3** 某轮手动选择的模型只写入该轮的接力配置，不回写项目默认。
- **FR-4** 重试某轮时沿用该轮已保存的 `zcode_model`。
- **FR-5** 每轮执行请求（运行证据 `evidence.json` 的 `request`）记录该轮 `zcode_model`；时间线显示同一值。
- **FR-6** 修改项目默认后，已创建接力的已用轮次保持原值；尚未开始的第二轮仍按 FR-2 预填新默认。

## 验收标准

- **AC-1**（S1/E1）保存默认后 `aep project zcode-default` 输出该值；`--clear` 后输出空；保存不可用的值被拒绝并报错。
- **AC-2**（FR-1/E5）新建接力，模型栏等于当前项目默认；切换项目后随之变化。
- **AC-3**（FR-2/E4）设默认 A，第一轮改选 B 并通过：第一轮记录为 B；第二轮预填为 A。
- **AC-4**（S4/FR-3）第二轮选择「使用客户端默认」：第二轮证据 `request` 不含 `zcode_model`，项目默认仍为 A。
- **AC-5**（S5/FR-4）第二轮失败后重试，证据 `request` 的 `zcode_model` 与失败那次相同，即使其间项目默认已改为 C。
- **AC-6**（FR-5/S6）两轮结束后重开 Studio，时间线逐轮显示与各自证据 `request` 一致的模型；ZCode 作为审查端时按 `reviewer_model` 优先、否则按 `zcode_model` 显示。
- **AC-7**（FR-6）第一轮已完成后把默认由 A 改为 C：第一轮仍显示原值，第二轮预填 C。
- **AC-8**（E6）旧接力记录可正常打开，不报错且不显示模型。
- **AC-9**（保留已有实现）不修改现有产品代码即可满足以上标准；若验证发现缺口，只记录为缺陷，不在本阶段修复。

## 验证方式

- 自动：`cargo test --locked`（含 `project::` 与桌面 `relay` 相关测试）；`cargo check --locked --manifest-path desktop/Cargo.toml --all-targets`。
- 两轮场景：使用本机测试替身，不消耗模型额度，不调用真实 ZCode。按 AC-3 → AC-5 → AC-7 的顺序走一次，保存每轮证据中的 `request` 对象和时间线截图。
- 真实 GUI 点选需可访问 macOS 桌面服务，不可用时在结论中注明未覆盖。

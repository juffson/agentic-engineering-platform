# 交互设计：项目 · 从多仓库文件夹创建项目

依据：`spec.md`（S1–S8、R1–R18、E1–E16、AC-1–AC-12）。本文规定操作者在哪里看到什么、各种状态怎么变化。扫描实现、接口结构、读取授权留给技术方案。只改 `studio/`（Tauri 前端），另外规定 CLI 的输出文字。

对 PRD 待确认项，界面按以下方式处理（技术方案可以调整上限数值，但不改交互）：

| 项 | 界面处理 |
|---|---|
| Q1 扫描深度 | 默认 2 层。清单底部固定提示「只查找了 2 层子目录」，旁边有「再查一层」链接，最多查到 4 层。CLI 用 `--depth N`。 |
| Q2 自动发现新仓库 | 不自动发现。仓库页的工作区卡片提供「重新扫描」，复用「添加仓库」的勾选清单（§4.3）。「导入 / 同步」不变。 |
| Q3 多个工作区根 | 每个项目只记录一个。第二个工作区文件夹只贡献仓库，界面给一行说明（§3.5、§4.2）。 |
| Q4 修改或清除工作区根 | 只读展示，不提供修改或清除。 |

## 0. 不改的部分

- 选择普通 git 仓库（或仓库里的子文件夹）时，新建项目对话框、导入区、「添加仓库」的行为和外观与现在完全一致（AC-4）。
- `pickFolder` 仍然把仓库内的子文件夹解析为仓库根（E1）。
- 仓库页已添加列表 `RepoRow` 的展开、仓库记忆、「远端与交付」、「导入 / 同步」、「在访达中显示」都不变。
- 新建事项对话框的仓库选择不变（S8、R18）。工作区根不是仓库，不会出现在可选列表里。

## 1. 用户路径

**P1 从工作区文件夹新建项目（S1、S2，AC-1、AC-2）**
1. 侧边栏「新建项目」→ 点「选择文件夹…」→ 选择 `03-行情基础数据计算存储`。
2. 路径写入「仓库路径」文本框，项目名为空时自动填成 `03-行情基础数据计算存储`。
3. 文本框下方出现文件夹清单区（§3.2），先显示「正在查找 git 仓库…」，随后显示「在 03-行情基础数据计算存储 下找到 11 个 git 仓库」和 11 行勾选项，默认全选。
4. 被勾选的仓库开始做导入扫描（查找可导入的记忆和分支），导入区显示为汇总折叠形式（§3.4）。
5. 主按钮显示「创建项目（11 个仓库）」。用户取消勾选 2 个后变成「创建项目（9 个仓库）」，被取消的仓库不再参与导入。
6. 点击创建：成功时出现 toast「项目已创建」，然后按现有逻辑导入选中的记忆和分支，对话框关闭，进入新项目。项目记录工作区根。

**P2 选错文件夹（S3，AC-3）**
1. 选择一个不含仓库的文件夹 → 清单区显示「正在查找 git 仓库…」→ 变为错误行（§3.3）：「这个文件夹和它的子目录里没有 git 仓库（已查找 2 层）」，旁边有「再查一层」。
2. 「创建项目」不可用，按钮悬停提示「先处理上面标红的路径」。
3. 用户可以从文本框删掉这一行，也可以再查一层。删掉后清单区消失，按钮恢复。

**P3 普通仓库（S4，AC-4）**
- 和现在一样：选择后不出现清单区，导入区照常展开显示。

**P4 混填（E8、E9）**
- 文本框每行一个路径。普通仓库行和工作区行可以同时出现，每个工作区行各有一块清单区。按钮上的数字是去重后的仓库总数。

**P5 往已有项目补仓库（S5，AC-5）**
1. 仓库页 → 「选择文件夹…」→ 选择工作区文件夹，路径填入输入框（和现在一样，不会自动添加）。
2. 点「添加仓库」：
   - 如果是普通仓库，直接添加，和现在一样；
   - 如果是工作区文件夹，在添加栏下方展开清单卡片（§4.2），按钮变为「正在查找…」后恢复。
3. 清单中，已在项目里的仓库显示为灰色、勾选且禁用，后面标「已添加」。其余仓库默认勾选。
4. 点「添加所选（9）」→ toast「已添加 9 个仓库」→ 清单卡片收起，输入框清空。下方已添加列表出现新增仓库，项目还没有工作区根时，上方出现工作区卡片（§4.1）。

**P6 重新扫描工作区根（Q2）**
- 工作区卡片 →「重新扫描」→ 在卡片下方展开同一份清单（§4.2），只是来源固定为工作区根。没有新仓库时显示「没有新的仓库，N 个都已在项目里」。

**P7 CLI（S7，AC-9）**：见 §6。

## 2. 统一文本

### 2.1 路径识别结果（新建项目和添加仓库共用一个格式函数）

| 结果 | 文本 | 样式 |
|---|---|---|
| 识别中 | 正在查找 git 仓库… | Spinner + `field-hint` |
| 普通仓库 | （不显示，按现状处理） | — |
| 工作区，有仓库 | 在 `<文件夹名>` 下找到 N 个 git 仓库 | 清单标题 |
| 工作区，没有仓库 | 这个文件夹和它的子目录里没有 git 仓库（已查找 D 层） | `inline-error` |
| 路径不存在 | 路径不存在：`<path>` | `inline-error` |
| 不是文件夹 | 不是文件夹：`<path>` | `inline-error` |
| 扫描达到上限（E7） | 文件夹太多，只列出了前面找到的仓库，结果可能不完整 | 清单底部 `field-hint`，警告色 |
| 识别失败（其他原因） | 无法读取这个文件夹：<原因> | `inline-error` |

任何界面都不能出现 `git rev-parse`、`fatal: not a git repository` 这类原始文字（AC-3）。

### 2.2 清单行

```
[✓] genki-api                    genki-api
[✓] quote-data-service           services/quote-data-service     ← 深层仓库显示相对路径
[✓] genki-core      已添加                                       ← 仅「添加仓库」：灰色、禁用
```

- 左侧是复选框和目录名（粗体）。右侧用 `muted mono` 显示相对工作区根的路径；相对路径和目录名相同时不重复显示。
- 同名仓库（E10）靠相对路径区分，不额外处理。
- 鼠标悬停显示完整的绝对路径（`title`）。
- 排序按相对路径，和后端返回的顺序一致。

### 2.3 清单头

```
在 03-行情基础数据计算存储 下找到 11 个 git 仓库        已选 11/11   [全选] [全不选]
```

- 「全选」「全不选」是文本按钮。已经全选时「全选」禁用，全不选时「全不选」禁用。
- 「添加仓库」的清单里，「已选 k/m」只统计可勾选的仓库，已添加的不算。

### 2.4 清单脚注

```
只查找了 2 层子目录 · 再查一层
```

- 第 4 层时只显示「已查找 4 层子目录」，不再有链接。
- 点「再查一层」后，脚注变为 Spinner「正在查找…」。新结果替换整个清单，但保留用户已取消的勾选（按绝对路径记），新出现的仓库默认勾选。

## 3. 新建项目对话框（`NewProjectDialog`）

### 3.1 布局

```
新建项目
  项目名称  [03-行情基础数据计算存储          ]
  仓库路径  ┌──────────────────────────────────────┐
           │/Users/.../03-行情基础数据计算存储        │
           └──────────────────────────────────────┘
           [选择文件夹…]
           选择本地 git 仓库文件夹，或包含多个仓库的工作区文件夹；每行一个绝对路径。之后也可以在「仓库」页添加。   ← hint 改写
  ┌ 文件夹清单区（每个工作区行一块，§3.2）─────────────┐
  └──────────────────────────────────────────────┘
  导入区（§3.4）
                                  [取消] [创建项目（11 个仓库）]
```

- 选择器提示语从「选择项目的 git 仓库文件夹」改为「选择 git 仓库文件夹，或包含多个仓库的工作区文件夹」。仓库页的选择器同样改写。
- 对话框宽度保持 620，内容超高时对话框主体滚动（沿用 Modal 现有行为）。

### 3.2 文件夹清单区

- 触发时机与现在的导入扫描相同：选择文件夹后立即识别；文本框失焦时，对每一行没识别过的路径做识别。同一路径不会重复识别。
- 每块清单区的结构：清单头（§2.3）、勾选列表（§2.2）、脚注（§2.4）。另外在清单头下方用一行 `field-hint` 写明「将记录为项目工作区根；顶层的 AGENTS.md 会提供给各阶段 Agent」。说明文件按实际找到的写：只有 CLAUDE.md 就写 CLAUDE.md，两个都有写「AGENTS.md、CLAUDE.md」，都没有就不显示后半句。
- 列表超过 8 行时，列表区域限高约 8 行并内部滚动，清单头和脚注保持可见。
- `data-testid`：清单区 `folder-scan`，行 `folder-scan-row`，头部计数 `folder-scan-count`。

### 3.3 错误行

- 识别为没有仓库、路径不存在、不是文件夹时，在清单区位置显示一行 `inline-error`（文本按 §2.1），并带一个「移除这一行」文本按钮。点击后从文本框删除这条路径。没有仓库的情况另外显示「再查一层」。
- 只要还有错误行，「创建项目」就不可用。

### 3.4 导入区（仓库多时）

现在每个仓库都显示一块完整的 `ImportSection`，11 个仓库会太长。规则如下：

- 普通仓库行：保持现状。
- 工作区展开出来的仓库：只对勾选的仓库做导入扫描，并发数由技术方案定。扫描完成后：
  - 有可导入内容的仓库，各显示一块 `ImportSection`，默认折叠，标题行显示「从 Claude / Codex / ZCode 导入 · genki-api · 记忆 3 条、分支 1 个」，点击展开；
  - 没有可导入内容的仓库，合并成一行 `field-hint`：「另外 7 个仓库没有可导入的记忆或分支」。
- 取消勾选一个仓库时，它的导入块立即消失，也不会导入。重新勾选时，用已有的扫描结果，不重复扫描。
- 扫描进行中的提示沿用现有文字，后面加进度：「正在查找 Claude / Codex / ZCode 里可导入的记忆和分支…（4/11）」。按钮显示「正在查找可导入内容…」并禁用，和现在一样。
- 单个仓库导入扫描失败时，和现在一样静默跳过：该仓库不显示导入块，不影响创建。

### 3.5 「创建项目」按钮

| 情况 | 按钮 |
|---|---|
| 名称为空 | 禁用（现状） |
| 还有识别中的路径或导入扫描 | 禁用，「正在查找可导入内容…」 |
| 存在错误行 | 禁用，title「先处理上面标红的路径」 |
| 有工作区清单但全不选，且没有其他仓库 | 禁用，title「至少选择一个仓库」 |
| 正常 | 「创建项目（N 个仓库）」。N 是去重后的总数；没有任何工作区行时保持原来的文案「创建项目」 |
| 提交中 | busy |

- 有两个以上工作区行时，清单区上方加一行 `field-hint`：「项目只记录一个工作区根：<第一个文件夹名>；其他文件夹只添加其中的仓库」。
- 文本框里填的路径不是一行都没有时，行为照旧：允许创建没有仓库的项目。

### 3.6 创建失败

- 后端报错（例如 E14：某个仓库在确认前被删除）时，出现 toast `act` 的错误，内容由后端点名，例如「genki-kline 不再是 git 仓库：<路径>」。对话框保持打开，勾选状态不丢，按钮恢复可用。
- 界面按「整体失败，什么都没创建」来处理。技术方案必须保证后端也是这样，否则要回到本文调整。
- 失败后对出错的工作区行自动重新识别一次，让清单反映最新状态。

## 4. 仓库页（`ReposPage`）

### 4.1 工作区卡片

项目有工作区根时，在添加栏和「已添加」之间显示：

```
┌ 工作区 ─────────────────────────────────────────────────────┐
│ 📁 03-行情基础数据计算存储                     [重新扫描] [📂]│
│    /Users/sirius/Desktop/cowork/market-data/03-行情基础数据计算存储 │
│    说明文件：AGENTS.md · 各阶段开始前会读取                        │
└────────────────────────────────────────────────────────────┘
```

- 说明文件行的几种情况：
  - 有说明文件：「说明文件：AGENTS.md、CLAUDE.md · 各阶段开始前会读取」，文件名用 `code` 样式；
  - 没有：「顶层没有 AGENTS.md 或 CLAUDE.md，阶段不会额外读取说明」（`muted`）；
  - 工作区根不存在（E11）：整行变为警告色「找不到这个文件夹，阶段不会读取工作区说明」，「重新扫描」禁用。
- 📂 是「在访达中显示」（复用 `api.reveal`）。
- 不提供修改或清除入口（Q4）。
- 没有工作区根的项目不显示这张卡片，页面与现在一致。
- `data-testid`：`workspace-root`。

### 4.2 「添加仓库」命中工作区

- 添加栏不变。点「添加仓库」或在输入框按 Enter 时：
  - 普通仓库：保持现状（toast「仓库已添加」，清空输入框）；
  - 工作区文件夹：主按钮显示 busy，识别完成后，在添加栏卡片内部、输入行下方展开清单（§2.2–§2.4），底部有按钮行 `[取消] [添加所选（k）]`；
  - 错误：在输入行下方显示 `inline-error`（§2.1），输入框保留原值。
- 清单展开期间修改输入框内容，清单收起（结果作废）。
- 已在项目里的仓库：勾选且禁用，标「已添加」。全部都已添加时，不显示勾选列表，只显示「这些仓库都已在项目里」和「关闭」按钮。
- 「添加所选（k）」在 k=0 时禁用。
- 添加成功：toast「已添加 k 个仓库」。如果项目原来没有工作区根，toast 改为「已添加 k 个仓库，并记录为项目工作区」。项目已有另一个工作区根时（Q3），toast 改为「已添加 k 个仓库；项目工作区仍是 <原文件夹名>」。
- 添加失败：toast 显示错误，清单保留。界面同样按整体失败处理（同 §3.6）。

### 4.3 重新扫描

- 工作区卡片的「重新扫描」：按钮 busy，然后在卡片内部展开 §4.2 的同一份清单，交互完全相同。
- 没有新仓库时，在卡片内显示一行「没有新的仓库，N 个都已在项目里」，3 秒后或点击别处时收起。

### 4.4 已添加列表

- 不变。工作区内的仓库不分组，也不另加标记，保持列表简单。

## 6. CLI 输出（R15–R17，AC-9）

所有输出都写到 stdout。错误按现有习惯写到 stderr，退出码 1。

**不带 `--all`，路径是工作区文件夹：**

```
$ aep project create 行情 --repository ~/Desktop/cowork/market-data/03-行情基础数据计算存储
/Users/sirius/Desktop/cowork/market-data/03-行情基础数据计算存储 不是 git 仓库，在它下面找到 11 个仓库（查找 2 层）：
  genki                 /Users/.../03-行情基础数据计算存储/genki
  genki-api             /Users/.../03-行情基础数据计算存储/genki-api
  ...
加 --all 全部添加，或用 --repository 逐个指定；更深的仓库用 --depth N。
```

退出码 1，项目未创建。`add-repo` 也是这样输出，提示中的 `--repository` 改为「逐个 add-repo」。

**带 `--all`：** 沿用现有的 JSON 输出习惯：

- `create` 输出 `{"project": "<id>", "workspace_root": "<path>", "repositories": [...]}`；
- `add-repo` 输出 `{"added": [...], "existing": [...], "workspace_root": "<path>" | null, "note": "项目工作区仍是 <path>"（仅 Q3 情况）}`。

普通仓库的 `add-repo` 输出保持现状（打印仓库路径），不改格式，以免破坏现有脚本。

**没有仓库：** stderr 输出 `这个文件夹和它的子目录里没有 git 仓库（已查找 2 层）：<path>`，退出码 1。

**`--depth N`：** 取值 1–4，超出范围时报错「--depth 只能是 1 到 4」。

## 7. 界面需要的数据（给技术方案，不定结构）

- 路径识别接口：输入路径和深度，返回以下几种结果之一：
  - 普通仓库：仓库根；
  - 工作区：规范化后的根路径、实际查找的深度、仓库列表（绝对路径、相对路径、目录名）、是否达到上限、顶层说明文件列表；
  - 错误：带分类（不存在、不是文件夹、没有仓库、其他），前端按 §2.1 显示文案。
- 新建项目和添加仓库的接口要能接收展开后的仓库列表和工作区根（可选），而且整体成功或整体失败。
- `ProjectSummary` 新增工作区根信息：路径、是否存在、说明文件列表。

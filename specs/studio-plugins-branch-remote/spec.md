# PRD：Studio · 插件菜单与分支管理插件化

## 背景（已核实）

- 侧边栏左下角 `sidebar-foot`（`studio/src/components/Sidebar.tsx:59-77`）现有四个入口：项目记忆 / 仓库 / 分支 / Token 消耗。「分支」打开 `studio/src/components/Branches.tsx`。
- 分支数据来自 `studio/src-tauri/src/api.rs:1020` `branch_graph` → `aep::project::branches::graph`（`src/project/branches.rs`）。它只读本地分支、worktree 和提交图；`Branch.ahead/behind` 是**相对本仓库检出的 HEAD**，不是相对远端。`aep-stage/<id>` 分支被标注为对应事项。
- 已有「插件」雏形：`api.rs:1037-1145` 的 `tool_list` / `git_tools` / `open_git_tool`，探测 Fork、GitHub Desktop、Sourcetree、Tower、GitKraken、VS Code、Cursor、lazygit、tig、gitk，并读取 `<catalog>/plugins/git-tools.json` 的自定义命令；作用仅是「用外部程序打开目录」，在分支页（`Branches.tsx:137,226`）使用。
- 仓库内没有任何 GitHub/GitLab API 集成，也没有凭据（令牌）存储。`src/project/merge.rs` 只做本地快进，不执行远端命令。
- 前后端契约在 `studio/src/api/types.ts`，浏览器预览用 `studio/src/api/mock.ts`，两者需同步。

> 说明：本次 `brief` 的「待确认问题」在「只读展示，还是要能 pu…」处被截断。本 PRD 按**只读联动**（不 push、不建/改 PR/MR、不合并）定范围，理由：与 `merge.rs`「不执行远端命令」及平台「不要推送、合并或发布」的一贯约束一致。若原意包含 push 或创建 PR/MR，请在确认本 PRD 时指出（见 Q1）。

## 目标

在左下角提供统一的「插件」入口，让用户能看到、启用、停用、配置插件。分支管理成为第一个以插件形式接入的功能；新增 GitHub、GitLab 两个插件，让分支页在本地分支之外显示远端分支、本地与远端的领先 / 落后，以及对应 PR/MR 的链接和状态。

## 术语

- **插件**：Studio 内置、可按项目或全局启用/停用并带配置的功能单元。本期只有内置插件，不加载外部代码。
- **分支管理插件**：现有分支页及其外部 git 工具打开能力。
- **远端插件**：GitHub 插件、GitLab 插件，负责远端分支与 PR/MR 信息。
- **远端（remote）**：仓库 `git remote` 中配置的远端，默认 `origin`。

## 用户场景

- **S1 打开插件菜单**：点击左下角「插件」，看到插件列表：名称、简介、状态（已启用 / 已停用 / 需要配置 / 出错）。
- **S2 启用/停用**：在列表中切换某插件的启用状态；停用分支管理插件后，左下角「分支」入口消失，再启用即恢复。
- **S3 配置 GitHub**：填写主机（默认 `github.com`，可改为 GitHub Enterprise 地址）和个人访问令牌，点击「测试连接」看到账号名或明确的错误。
- **S4 配置 GitLab**：同上，主机默认 `gitlab.com`，可填自建实例地址。
- **S5 分支页看远端**：在分支页，每个本地分支旁显示其上游远端分支、相对远端的领先 N / 落后 M；另列出只存在于远端的分支。
- **S6 看 PR/MR**：分支有对应的打开中、已合并或已关闭的 PR/MR 时，显示编号、标题、状态，点击在系统浏览器中打开。
- **S7 事项分支**：`aep-stage/<id>` 分支同时显示所属事项（现有）与远端/PR 信息（如果已被推送）。
- **S8 刷新**：分支页可手动刷新远端信息；显示上次刷新时间。
- **S9 外部 git 工具**：现有「用外部工具打开」功能继续可用（并入分支管理插件，或保持原样，由技术方案决定）。

## 范围

**包括**
- 左下角「插件」入口与插件菜单（列表、启用/停用、配置、测试连接）。
- 插件机制的最小形态：内置插件注册表、启用状态与配置的持久化、Studio 根据启用状态显示/隐藏对应入口。
- 分支管理作为第一个插件接入（行为不退化）。
- GitHub、GitLab 插件：只读获取远端分支、ahead/behind、PR/MR 链接与状态。
- `types.ts` 与 `mock.ts` 同步更新，浏览器预览可演示全部状态。

**不包括**
- 插件市场、远程下载、安装第三方插件、第三方代码执行沙箱。
- GitHub、GitLab 以外的平台（Gitea、Bitbucket、Azure DevOps 等）。
- 任何写远端的操作：push、创建/更新/合并/关闭 PR/MR、删除远端分支、评论（见 Q1）。
- 修改事项工作流的合并/交付逻辑（`merge.rs` 保持本地快进）。
- OAuth 设备流/浏览器登录（本期只支持个人访问令牌，见 Q3）。

## 功能需求

### 插件菜单与机制
- **FR-1** 左下角新增「插件」入口，与现有 foot-link 同样式；无打开的项目时仍可打开（全局插件配置不依赖项目）。
- **FR-2** 插件菜单列出全部内置插件：分支管理、GitHub、GitLab。每项显示名称、一句话说明、状态徽标（已启用 / 已停用 / 需要配置 / 出错）。
- **FR-3** 每个插件可单独启用/停用，状态持久化，重启 Studio 后保持。默认值：分支管理=启用；GitHub、GitLab=停用。
- **FR-4** 停用分支管理插件时，左下角「分支」入口隐藏，若当前正在分支页则回到事项页；GitHub/GitLab 插件依赖分支管理插件，分支管理停用时它们显示为「不可用（依赖分支管理）」，不可单独启用。
- **FR-5** 插件配置面板：GitHub/GitLab 有「主机地址」「访问令牌」两个字段和「测试连接」「保存」「清除令牌」操作；分支管理面板显示外部 git 工具列表及自定义配置文件路径（沿用现有 `git_tools` 的 `config`）。
- **FR-6** 测试连接成功时显示令牌对应的账号名；失败时按类别给出明确中文提示：主机不可达、令牌无效或过期、权限不足、证书错误。

### 凭据
- **FR-7** 令牌不得以明文写入项目文件、事项档案、运行证据、日志或 `types.ts` 返回给前端的任何结构；保存后前端只能看到「已设置」及掩码（如末 4 位）。存储位置（如 macOS 钥匙串）由技术方案决定。
- **FR-8** 主机地址仅接受 `https://`（或省略协议时补全为 `https://`）；去掉末尾 `/` 后保存。

### 远端匹配
- **FR-9** 对每个仓库，按其 `git remote` URL（支持 HTTPS 与 SSH 形式）匹配已启用的远端插件：主机与插件配置的主机一致才算匹配，并解析出 owner/repo（GitLab 可含多级 group）。
- **FR-10** 没有匹配插件的仓库，分支页只显示本地信息并提示「未配置与 <主机> 对应的插件」，不报错。

### 分支页远端信息
- **FR-11** 每个本地分支显示其上游（`branch.<name>.merge` 对应的远端分支）；有上游时显示相对上游的领先/落后数，计算基于本地已有的远端跟踪引用（`refs/remotes/...`）。现有「相对 HEAD 的 ahead/behind」保留，两者在界面上可区分。
- **FR-12** 分支页可列出只存在于远端、本地没有对应分支的远端分支（可折叠，默认折叠）。
- **FR-13** 「刷新远端」操作：执行一次只读的 `git fetch`（不改工作区、不改本地分支）更新远端跟踪引用，并通过插件 API 拉取 PR/MR；显示上次刷新时间。打开分支页时不自动 fetch（见 Q2）。
- **FR-14** PR/MR 匹配：以分支名作为 head/source branch，在匹配到的远端仓库中查找；显示最近一个的编号、标题、状态（打开 / 草稿 / 已合并 / 已关闭）。点击在系统浏览器打开其网页地址。
- **FR-15** 远端请求失败（网络、限流、认证）时，分支页仍显示本地图，并在远端区域显示错误与「重试」，不阻塞页面。
- **FR-16** 远端请求有超时（默认 15 秒）且不在主线程阻塞 UI；同一仓库的刷新在进行中时再次点击不会重复发起。

### 兼容
- **FR-17** 现有分支页功能（提交图、worktree、事项标注、用外部工具打开）在任何插件组合下不退化。
- **FR-18** 已存在的 `<catalog>/plugins/git-tools.json` 继续被读取，自定义工具仍出现在列表中。

## 边界情况

- **E1** 仓库没有任何 remote：不显示远端区域，只提示「此仓库没有配置远端」。
- **E2** 多个 remote（如 `origin` + `upstream`）：上游以分支跟踪配置为准；PR/MR 查询默认使用 `origin`，无 `origin` 时用第一个匹配插件的 remote。
- **E3** remote 为 SSH 形式（`git@github.com:o/r.git`、`ssh://git@host:2222/g/sub/r.git`）：能正确解析主机与路径。
- **E4** GitHub Enterprise / 自建 GitLab 使用自签名证书：测试连接给出证书错误提示，本期不提供跳过校验的开关（见 Q4）。
- **E5** 令牌过期或被撤销：插件状态变为「出错」，分支页远端区域提示重新配置；本地内容正常。
- **E6** API 限流（GitHub 403/429、GitLab 429）：提示限流和重置时间，不自动重试轰炸。
- **E7** 分支名含 `/`、中文或特殊字符：查询时正确编码。
- **E8** 一个分支对应多个 PR/MR：显示最新一个，并标注「另有 N 个」。
- **E9** 本地分支无上游但远端存在同名分支：显示「未跟踪，远端有同名分支」，不自动设置上游。
- **E10** 尚未 fetch 过、远端跟踪引用缺失：ahead/behind 显示「未知」，提示刷新。
- **E11** fetch 需要凭据（HTTPS remote）而系统 git 凭据不可用：fetch 失败提示，不使用插件令牌改写 git 配置（见 Q5）。
- **E12** Studio 离线：插件菜单仍可打开和修改启用状态；测试连接给出不可达提示。
- **E13** 两个插件都启用且主机不同：各仓库按主机匹配各自插件，互不干扰。
- **E14** 浏览器预览（mock）环境：不发任何网络请求，用固定样例展示各状态。

## 验收标准

- **AC-1**（FR-1/FR-2）左下角出现「插件」入口；点击后列出分支管理、GitHub、GitLab 三项，各有说明和状态徽标；未打开任何项目时入口仍可用。
- **AC-2**（FR-3）首次启动默认状态为：分支管理启用、GitHub 停用、GitLab 停用；改变状态后重启 Studio，状态保持。
- **AC-3**（FR-4）停用分支管理：「分支」入口消失；若停用时在分支页，页面回到事项页；GitHub/GitLab 显示为不可用。重新启用后入口恢复。
- **AC-4**（S3/FR-6）用有效令牌测试连接 github.com 显示账号名；用无效令牌显示「令牌无效或过期」；主机写错显示「主机不可达」。GitLab 同理（AC 以本地测试替身或可选真实账号验证）。
- **AC-5**（FR-7）保存令牌后：`<catalog>` 下所有 JSON 文件、事项档案、运行证据、Studio 日志中均搜不到该令牌字符串（`grep -r` 验证）；前端拿到的插件配置只有掩码。
- **AC-6**（FR-8）主机填 `http://x` 被拒绝；填 `gitlab.example.com/` 保存为 `https://gitlab.example.com`。
- **AC-7**（FR-9/E3）单元测试覆盖 remote URL 解析：HTTPS、`git@host:o/r.git`、`ssh://git@host:port/g/sub/r.git`、带 `.git` 与不带 `.git`，主机与路径解析正确。
- **AC-8**（FR-10/E1）无 remote 或无匹配插件的仓库，分支页显示对应提示，本地图正常，无错误弹窗。
- **AC-9**（FR-11/E10）在测试仓库中构造本地分支领先上游 2、落后上游 1：分支页显示「↑2 ↓1（相对 origin/xxx）」，并与原有相对 HEAD 的数值分开显示；删除远端跟踪引用后显示「未知」。
- **AC-10**（FR-12/E9）远端独有分支出现在默认折叠的「仅远端」分组；本地无上游但远端有同名分支时显示「未跟踪」提示。
- **AC-11**（FR-13/FR-16）点击「刷新远端」后执行 fetch 并更新显示与「上次刷新」时间；刷新中再次点击不重复发请求；本地分支 sha 与工作区文件在刷新前后不变。
- **AC-12**（FR-14/E8）用替身 API 返回打开、草稿、已合并、已关闭四类 PR/MR：分支页状态标签正确；点击在系统浏览器打开对应网址；多条时显示最新一条并标「另有 N 个」。
- **AC-13**（FR-15/E5/E6）替身 API 返回 401、429、超时：分支页本地内容可用，远端区域分别显示认证失败（插件状态变「出错」）、限流及重置时间、超时并可重试。
- **AC-14**（S7）`aep-stage/<id>` 分支同时显示事项标注与 PR/MR 信息。
- **AC-15**（FR-17/FR-18/S9）现有「用外部工具打开」列表与 `git-tools.json` 自定义命令仍可用；关闭所有远端插件时分支页与改动前行为一致。
- **AC-16**（E14）`mock.ts` 覆盖：插件列表各状态、远端 ahead/behind、仅远端分支、四类 PR/MR、错误态；`npm run build`（含类型检查）通过。
- **AC-17**（不做范围）代码中不存在对远端的写操作（push、创建/更新 PR/MR 的 API 调用）。

## 验证方式

- 自动：`cargo test --locked`（remote URL 解析、上游 ahead/behind、令牌不落盘、插件状态持久化）；`cargo check --locked --manifest-path studio/src-tauri/Cargo.toml`；`studio` 下 `npm run build` 与现有前端测试。
- 远端 API 用本地 HTTP 替身（不消耗真实账号额度、不访问外网）；真实 github.com / GitLab 连接为可选人工验证，不可用时在结论中注明未覆盖。
- GUI：在 Studio 中按 AC-1 → AC-3 → AC-9 → AC-12 走一遍并截图；无法访问 macOS 桌面服务时注明。

## 开放问题

- **Q1**（brief 截断处）「联动仓库」是否只读？本 PRD 暂定只读，push / 创建 PR/MR 不做。若需要，建议作为后续事项，并单独设计确认与审计流程。
- **Q2** 打开分支页时是否自动 fetch？暂定否（仅手动刷新），避免意外网络与凭据弹窗。
- **Q3** 是否需要 OAuth / `gh auth token` / `glab` 等已有登录复用？暂定只支持手填个人访问令牌。
- **Q4** 自签名证书的自建实例是否需要「信任此证书」选项？暂定不提供。
- **Q5** fetch 使用系统 git 凭据还是插件令牌？暂定系统 git 凭据，插件令牌只用于 API。
- **Q6** 插件启用状态是全局还是按项目？暂定全局（凭据与主机天然是用户级），技术方案可改为「全局配置 + 项目级启用」。
- **Q7** 现有 git-tools 是否并入新插件机制（如迁入分支管理插件的配置）？由技术方案决定，约束为 AC-15。

# 交互设计：Studio · 插件菜单与分支管理插件化

依据：`spec.md`（S1–S9、FR-1–18、E1–14、AC-1–17），按 PRD 暂定结论设计：只读联动（Q1）、不自动 fetch（Q2）、只用个人访问令牌（Q3）、插件启用状态全局（Q6）。本文只定义操作者看到什么、在哪里、各状态怎么变化；插件注册、持久化、令牌存放、fetch 实现留给技术方案。界面只改 `studio/`（Tauri），GPUI `desktop/` 不改。

## 0. 不改的部分

- 侧边栏上半部分（项目切换、新建事项、事项分组）不变；左下角现有四个入口的样式、顺序不变。
- 分支页的提交图（泳道、提交行、分支 chip、高亮与滚动定位）、仓库下拉、「刷新」（重读本地）、「访达」与外部工具按钮行为不变。
- 事项页头部的 `branch-chip`（`WorkPage.tsx:190`，在访达中显示工作区）不变，不跳到分支页。
- **所有远端插件都停用时，分支页与改动前完全一致**（AC-15）。唯一例外：页底「外部工具插件」那段说明移到插件页（§3.4），分支页留一行链接（§4.6）。
- 不出现任何写远端的按钮或菜单（push、创建/合并/关闭 PR/MR、删除远端分支）。PR/MR 只有「在浏览器打开」。

## 1. 用户路径

**P1 打开插件菜单（S1，AC-1）**
1. 左下角最后一项「插件」（图标 `Puzzle`）。点击进入「插件」页，入口高亮。
2. 页面列出三张插件卡：分支管理、GitHub、GitLab，每张有名称、一句话说明、状态徽标、启用开关（§3.2）。
3. 没有打开任何项目时，入口仍可点；插件页照常显示（§3.1）。

**P2 启用 / 停用（S2，AC-2、AC-3）**
1. 在卡片右侧拨开关，立即保存，不需要再点「保存」；成功无 toast，失败 toast「保存插件状态失败：<原因>」并把开关拨回。
2. 停用「分支管理」：左下角「分支」入口立刻消失；GitHub、GitLab 卡的开关变灰，徽标变「不可用」，说明行显示「需要先启用分支管理」。
3. 重新启用「分支管理」：「分支」入口恢复；GitHub/GitLab 恢复到停用前各自的开关状态（它们自己的开关值保留，只是暂时不生效）。

**P3 配置 GitHub / GitLab（S3、S4，AC-4、AC-6）**
1. 在 GitHub 卡点「配置」（或开启了一个还没有令牌的插件时自动展开），卡片原地展开配置区（§3.3）。
2. 主机地址预填 `github.com`（GitLab 为 `gitlab.com`）；粘贴令牌。
3. 点「测试连接」→ 按钮转圈 →「已连接为 octocat」或分类错误（§2.2）。
4. 点「保存」→ 令牌框清空，变成「已设置 · ••••a1b2」，徽标按 §2.1 更新。
5. 以后要换令牌点「更换」；不用了点「清除令牌」（确认后清除）。

**P4 在分支页看远端（S5、S6、S7，AC-9、AC-10、AC-12、AC-14）**
1. 启用并配置 GitHub 后打开「分支」。页头下出现一条远端状态栏（§4.2）：`origin · github.com/acme/aep · GitHub · 尚未刷新远端`。
2. 分支列表每行多一行远端比较（§4.3）；有 PR 的分支右上角出现 PR 标签（§4.4），`aep-stage/…` 事项分支同样显示，且「事项：…」行保留。
3. 列表底部有默认折叠的「仅远端 N」分组（§4.5）。
4. 选中分支后，提交图上方工具栏下多一行远端详情：上游、领先落后、PR 标题和「在浏览器打开」。

**P5 刷新远端（S8，AC-11、AC-13）**
1. 点状态栏右侧「刷新远端」→ 按钮变「正在刷新…」并禁用；分支列表和提交图仍可操作，已有远端信息保持显示直到新结果回来。
2. 完成后状态栏显示「上次刷新 刚刚」；领先落后、仅远端分组、PR 标签更新。
3. 部分失败时（fetch 成功但 API 失败，或反之）只在状态栏下方出现对应错误行，带「重试」或「去配置」（§4.2）；本地内容不受影响，没有弹窗。

**P6 外部 git 工具（S9，AC-15）**
1. 分支页选中有工作区的分支 → 工具栏按钮和现在一样。
2. 想知道支持哪些工具 / 自定义命令写在哪里：插件页 → 分支管理 →「配置」看到工具列表和 `git-tools.json` 路径（§3.4）。

## 2. 统一文本

### 2.1 插件状态徽标（插件卡、分支页提示共用）

按顺序取第一个成立的：

| 条件 | 徽标 | 样式 | 卡片说明行补充 |
|---|---|---|---|
| GitHub/GitLab 且分支管理已停用 | 不可用 | 灰 | 需要先启用分支管理 |
| 开关关 | 已停用 | 灰 | — |
| 开关开、没有令牌（远端插件） | 需要配置 | 黄 | 填写访问令牌后才能读取远端信息 |
| 开关开、最近一次测试连接或远端请求因认证/权限/证书失败 | 出错 | 红 | 最近一次错误的分类文案（§2.2）+ 时间，如「令牌无效或过期 · 10 分钟前」 |
| 其他 | 已启用 | 主色 | — |

- 「出错」只由认证（401）、权限（403 非限流）、证书错误触发；网络不可达、超时、限流是暂时问题，不改插件徽标，只在分支页提示（E5、E6、E12）。
- 「出错」在下一次测试连接或远端请求成功后自动消失。
- 任一已启用插件处于「出错」时，左下角「插件」入口右侧显示一个红点（`dot dot-failed`，`aria-label="有插件出错"`）。

### 2.2 远端错误分类（测试连接、分支页共用一个格式函数）

| 类别 | 显示 | 附带操作 |
|---|---|---|
| 主机不可达（DNS、连接拒绝、离线 E12） | 无法连接 `<host>`，请检查地址和网络 | 重试 |
| 令牌无效或过期（401） | 令牌无效或过期，请在 `<平台>` 重新生成后更换 | 去配置 |
| 权限不足（403，非限流） | 令牌权限不足：GitHub 需要仓库读取和 Pull requests 读取；GitLab 需要 `read_api` | 去配置 |
| 证书错误（E4） | `<host>` 的 HTTPS 证书不受信任（暂不支持自签名证书） | 无 |
| 限流（GitHub 403+限流头 / 429，GitLab 429，E6） | 请求过多已被限流，约 `HH:mm` 后恢复 | 「重试」禁用到恢复时间，悬停提示恢复时间 |
| 超时（FR-16，15 秒） | `<host>` 15 秒内没有响应 | 重试 |
| 找不到仓库（404） | 在 `<host>` 上找不到 `<owner/repo>`，或令牌无权访问 | 去配置 |
| 其他 | `<host>` 返回 `<状态码>`：`<消息，最多 120 字>` | 重试 |

- 「去配置」= 跳到插件页并展开对应插件的配置区。
- 错误文案里绝不出现令牌，包括请求 URL 或响应回显（AC-5）。

### 2.3 PR / MR 状态标签

| 状态 | 标签 | 样式 |
|---|---|---|
| 打开 | `#123 打开`（GitLab 为 `!45 打开`） | 绿 |
| 草稿 | `#123 草稿` | 灰描边 |
| 已合并 | `#123 已合并` | 紫 |
| 已关闭（未合并） | `#123 已关闭` | 红淡 |
| 多条（E8） | 最新一条的标签后加 `+N`，悬停「另有 N 个 PR」/「另有 N 个 MR」 | 同最新一条 |

「最新」按创建时间取。标签整体是按钮：点击在系统浏览器打开 PR/MR 网址，不改变当前选中的分支；`title` 为完整标题。

### 2.4 远端比较文案（分支行与选中详情共用）

| 情形 | 显示 |
|---|---|
| 有上游，跟踪引用存在，有差异 | `↑2 ↓1（相对 origin/feat-x）` |
| 有上游，跟踪引用存在，无差异 | `与 origin/feat-x 一致` |
| 有上游，跟踪引用缺失（E10） | `相对 origin/feat-x 未知 · 刷新远端后再看` |
| 无上游，远端跟踪引用里有同名分支（E9） | `未跟踪 · 远端有同名分支 origin/feat-x` |
| 无上游，远端无同名 | `仅本地` |

- 原有「相对 HEAD 的领先 / 落后」在有远端插件生效时改写为 `相对 HEAD 领先 a · 落后 b`，用文字；远端比较用箭头和「相对 origin/…」，两者格式不同，同一行出现时以 ` · ` 隔开前后两段（AC-9）。没有远端插件生效时保持原文 `领先 a · 落后 b`。
- 上游的远端名不一定是 `origin`，按分支跟踪配置显示（E2）。

## 3. 插件入口与插件页

### 3.1 左下角入口

- `sidebar-foot` 现有四项之后加一条细分隔线，再放「插件」（`Puzzle` 图标）。和其他项同样式，`on` 态同样高亮。
- 「插件」**永不禁用**（其他四项在无项目时仍禁用）。
- 「分支」入口仅在分支管理插件启用时渲染；停用时整行移除（不是禁用），其他入口位置上移。
- 页面路由：`Page` 增加 `"plugins"`。插件页必须在「没有项目」的空状态判断之前渲染，所以无项目时点「插件」能进入插件页；从插件页点上半部分事项或切换项目时，按现有逻辑回到事项页。
- 当前页是 `branches` 而分支管理变成停用（例如设置在另一窗口改了，或启动时读到停用）：自动回到事项页，不提示（AC-3）。

### 3.2 插件页布局

沿用 `page` / `page-inner` / `page-head` 单列结构（同「仓库」页）：

```
插件
Studio 内置的扩展功能。只读取远端信息，不会推送或修改 PR/MR。

┌──────────────────────────────────────────────────────────────┐
│ [GitBranch] 分支管理                 [已启用]   配置  (●──) │
│ 分支页：本地分支、工作区、提交图，用外部 git 工具打开            │
├──────────────────────────────────────────────────────────────┤
│ [Github]   GitHub                    [需要配置]  配置  (●──) │
│ 在分支页显示 GitHub 远端分支、领先落后和 PR · github.com        │
├──────────────────────────────────────────────────────────────┤
│ [Gitlab]   GitLab                    [已停用]    配置  (──○) │
│ 在分支页显示 GitLab 远端分支、领先落后和 MR · gitlab.com        │
└──────────────────────────────────────────────────────────────┘
```

- 每张卡：图标、名称、徽标（§2.1）、「配置」文字按钮、开关（`role="switch"`、`aria-checked`、`aria-label="启用 <名称>"`）。第二行说明；远端插件说明末尾显示当前主机。有补充说明（§2.1 最后一列）时作为第三行，小字。
- 同一时间最多展开一张卡的配置区；点另一张的「配置」会收起当前那张（有未保存修改时见 §3.3 草稿规则）。
- 开启一个还没有令牌的远端插件时，自动展开它的配置区并把焦点放到令牌框。
- 「分支管理」不可用时（不会出现，它没有依赖），开关总可操作。GitHub/GitLab「不可用」时开关 `disabled`，悬停提示「需要先启用分支管理」；配置区仍可展开和保存（方便先配置后启用）。
- 加载：进入页面先显示三张卡的骨架（名称和说明是静态文字可直接显示，徽标和开关位置显示 `Spinner`），状态到达后替换。
- 读取失败：卡片区上方 `inline-error`「读取插件状态失败：<原因>」+「重试」；三张卡显示名称和说明，开关禁用。左下角「分支」入口在读取失败时**保持显示**（按默认启用处理，避免因读取失败丢入口）。
- 空数据：不会出现（三个内置插件固定存在）。

### 3.3 GitHub / GitLab 配置区

展开在卡片内部、说明行下方：

```
主机地址   [ github.com                         ]
           将保存为 https://github.com
访问令牌   [ ••••••••••••••••••••                ]   （未设置时）
           需要仓库读取和 Pull requests 读取权限。令牌存放在系统钥匙串，不写入任何文件。
   或      已设置 · ••••a1b2      [更换]  [清除令牌]          （已设置时）

[测试连接]  [保存]                         ✓ 已连接为 octocat
```

**主机地址（FR-8，AC-6）**
- 输入时不校验；失焦或点保存/测试时规整：去首尾空格，无协议补 `https://`，去末尾 `/`。规整后与输入不同时在下方提示「将保存为 https://gitlab.example.com」。
- 以 `http://` 开头或包含空格、不是合法主机：字段下方红字「只支持 https 地址」/「主机地址无效」，「测试连接」「保存」禁用。
- 主机为空：按默认主机处理，提示「留空将使用 github.com」。
- 预填值是 `github.com` / `gitlab.com`；GitHub 填其他主机时说明补一句「GitHub Enterprise 会使用 `https://<host>/api/v3`」（只是说明，路径由技术方案定）。

**访问令牌（FR-7，AC-5）**
- `type="password"`、`autocomplete="off"`、`spellcheck={false}`；不提供「显示明文」按钮。
- 未设置：空输入框 + 权限说明（GitHub：仓库读取 + Pull requests 读取，classic 令牌用 `repo`；GitLab：`read_api`）。
- 已设置：输入框不显示，换成「已设置 · ••••<末 4 位>」+「更换」「清除令牌」。点「更换」出现空输入框和「取消」，旧令牌在保存新令牌前仍有效。
- 保存成功后输入框立即清空，切回「已设置」显示。前端任何时候都拿不到已保存令牌的明文。

**测试连接**
- 用输入框里的令牌（如果正在输入）否则用已保存的令牌，配合当前主机输入值；不保存任何东西。
- 没有可用令牌时按钮禁用，悬停「先填写访问令牌」。
- 进行中：按钮 `busy`，文字「测试中…」，其他字段仍可编辑；再次点击无效。
- 成功：按钮右侧绿色「✓ 已连接为 <账号名>」。
- 失败：按钮右侧红色 §2.2 文案（不带「去配置」，因为已经在配置区）。
- 修改主机或令牌后，上一次测试结果立即清除。
- 用已保存令牌测试的结果会更新徽标（成功清除「出错」，认证失败置「出错」）；用未保存令牌测试不影响徽标。

**保存**
- 按钮在主机或令牌有改动、且主机合法时可用。保存不要求先测试成功；保存后不自动测试。
- 成功：toast「GitHub 配置已保存」，徽标按 §2.1 重算（开关开 + 有令牌 → 已启用）。
- 失败（例如钥匙串拒绝访问）：配置区底部 `inline-error`「保存失败：<原因>」，输入内容保留。

**清除令牌**
- `window.confirm("清除 GitHub 的访问令牌？分支页将不再显示 PR 信息。")`（与现有移除项目一致的确认方式）。
- 成功：toast「令牌已清除」；开关开着时徽标变「需要配置」。开关状态不变。

**草稿规则**
- 配置区内未保存的主机/令牌只存在组件状态里。收起卡片、切到其他页面时直接丢弃，不提示（令牌草稿不应长时间留在内存，也不写任何存储）。

### 3.4 分支管理配置区

```
外部 git 工具
  已检测到：Fork · VS Code · lazygit                    （无则「没有检测到已安装的工具」）
  自定义工具：<catalog>/plugins/git-tools.json   [在访达中显示]
  格式：[{"label":"Fork","command":["open","-a","Fork","{path}"]}]
```

- 工具列表来自现有 `gitTools()`（AC-15、FR-18），只读展示，标出哪些来自自定义配置（「自定义」小标签）。
- 「在访达中显示」：文件存在则选中文件；不存在则打开 `plugins/` 目录（目录也不存在时提示「文件还不存在，按上面格式新建即可」）。
- 读取工具失败：「读取外部工具失败：<原因>」，不影响开关。
- 没有其他可配置项；本期不在界面里编辑 `git-tools.json`（Q7 的并入方式由技术方案定，界面只需要上面三项数据）。

## 4. 分支页改动

### 4.1 生效条件

「远端功能生效」= 分支管理启用 且 GitHub 或 GitLab 至少一个启用（不论是否已配置令牌）。不生效时 §4.2–§4.5 全部不出现，页面与改动前一致。

### 4.2 远端状态栏

位置：`branches-head` 下方、`branches-body` 上方，一行，`card` 轻样式。按当前所选仓库显示，切换仓库时跟着切换。

```
[Github] origin · github.com/acme/aep · 上次刷新 3 分钟前                     [刷新远端]
```

| 状态 | 左侧内容 | 右侧 |
|---|---|---|
| 仓库没有 remote（E1） | 此仓库没有配置远端 | 无按钮 |
| 有 remote，没有匹配的已启用插件（FR-10） | `origin · gitlab.example.com/g/sub/r` · 未配置与 gitlab.example.com 对应的插件 · [打开插件] | 「刷新远端」（仅 fetch，见下） |
| 匹配到插件但该插件「需要配置」 | `origin · github.com/acme/aep` · GitHub 未填写访问令牌，PR 信息不可用 · [去配置] | 「刷新远端」 |
| 匹配到插件，从未刷新 | `origin · github.com/acme/aep` · 尚未刷新远端，领先落后基于本地已有的远端引用 | 「刷新远端」 |
| 已刷新 | `origin · github.com/acme/aep` · 上次刷新 3 分钟前（悬停显示具体时间） | 「刷新远端」 |
| 刷新中 | 同上，时间后加 `Spinner` | 「正在刷新…」禁用 |

- 图标随匹配到的插件显示 GitHub / GitLab；无匹配时显示通用 `Globe`。
- 多 remote（E2）：显示用于 PR 查询的那个（`origin` 优先），后面加「另有 1 个远端」，悬停列出名称和地址。
- 「刷新远端」做两件事：`git fetch`（只更新远端跟踪引用）；匹配到已配置插件时再拉 PR/MR。无匹配插件或无令牌时只 fetch。
- 刷新进行中再点无效（FR-16）；切到别的仓库再切回来，看到的仍是进行中或已完成的结果。离开分支页不取消刷新。
- 刷新完成后自动重读一次本地分支图（同「刷新」），不再额外提示成功。
- 「上次刷新」每分钟更新相对时间。

**错误行**（状态栏下方，`inline-error` 小号，可同时出现两行，各自独立）：
- fetch 失败：`git fetch 失败：<git 输出首行>`。认证类失败（E11）追加「Studio 用系统 git 凭据拉取，不会用插件令牌改写 git 配置」。操作：「重试」。
- API 失败：§2.2 文案 + 对应操作。限流时「重试」禁用到恢复时间。
- 失败不清除上一次成功的数据：已有的领先落后和 PR 标签保留，状态栏时间仍显示上次成功时间，错误行说明本次失败（FR-15）。
- 再次点刷新或重试时，错误行先清空。

### 4.3 分支行

在现有 `branch-row` 结构上加：

```
⎇ feat/plugins  [当前]                               [#123 打开 +1]
事项：插件菜单与分支管理插件化
相对 HEAD 领先 3 · 落后 0 · ↑2 ↓1（相对 origin/feat/plugins）
AEP 工作区 · 2 改动
```

- 第一行右侧：PR/MR 标签（§2.3）；没有 PR 或没拉过时不占位。
- 比较行：§2.4 两段。当前分支原来不显示相对 HEAD 的数，仍不显示，只显示远端那段。
- 工作区信息原来与领先落后同在 `branch-meta`，现在单独一行，避免一行过长。
- 刷新中、已有值保持显示；第一次刷新前没有 PR 数据时不显示任何占位。
- 筛选框（现有）同时匹配 PR/MR 编号（输入 `#123` 或 `123`）和标题。

### 4.4 选中分支后的远端详情

提交图工具栏（`graph-toolbar`）下方新增一行 `graph-remote`，仅在选中分支且远端功能生效时出现：

```
上游 origin/feat/plugins · ↑2 ↓1      #123 插件菜单与分支管理插件化 · 打开 · 另有 1 个   [在浏览器打开]
```

- 无上游：显示 §2.4 对应文案。
- PR 有数据：编号、完整标题（单行省略）、状态、「另有 N 个」、「在浏览器打开」。
- 已拉过 PR 但该分支没有：「没有对应的 PR」（GitLab「MR」）。
- 从没拉过 / 无匹配插件 / 无令牌：不显示 PR 段。
- 「在浏览器打开」走系统浏览器（与 PR 标签同一动作），不在 Studio 内嵌网页。

### 4.5 「仅远端」分组（FR-12，AC-10）

- 位置：分支列表底部，组头 `▸ 仅远端 5`，默认折叠；展开状态在本次会话内按仓库记住。
- 行内容：`⎇ origin/feat-y`（灰色图标区分本地分支）+ PR 标签 + 第二行「远端分支，本地没有」。
- 来源：本地已有的远端跟踪引用中、没有任何本地分支以它为上游或同名的分支；`origin/HEAD` 不列出。
- 点击：选中它；若其提交在当前提交图里则滚动并高亮；不在时工具栏显示「这个远端分支的提交不在本地提交图中」，没有外部工具按钮（它没有工作区）。不提供「检出」「建立本地分支」按钮（只读）。
- 数量为 0 时整个分组不显示；还没有任何远端跟踪引用时组头不显示，状态栏的「尚未刷新远端」已足够提示。
- 筛选框同样作用于该分组；筛选后为 0 时分组隐藏。

### 4.6 页底说明

现有「外部工具插件：已安装的 … 自定义工具写在 …」段落替换为一行：「外部工具：已检测到 N 个。查看支持的工具和自定义方法：插件 › 分支管理」，后半句是链接，跳插件页并展开分支管理配置区。

### 4.7 提交图

提交图与 ref chip 不变：远端跟踪引用不画成 chip，不新增泳道（避免图变复杂）；远端信息只在列表和详情行出现。

## 7. 界面需要的数据（给技术方案，不定结构）

- 插件列表：id、启用值、是否因依赖不可用、主机、令牌是否已设置 + 末 4 位、最近一次认证类错误（分类 + 时间）。不含令牌明文。
- 插件操作：设置启用、保存主机/令牌、清除令牌、测试连接（返回账号名或错误分类 + 限流恢复时间）。
- 分支页远端数据（按仓库）：remote 列表（名称、URL、解析后主机与路径、匹配插件）、上次成功刷新时间、是否刷新中；每个本地分支的上游名、上游跟踪引用是否存在、相对上游的 ahead/behind、同名远端分支；仅远端分支列表（名称、sha）；PR/MR（编号、标题、状态、网址、创建时间、同分支其余数量）；本次刷新 fetch 与 API 各自的错误分类。
- 「刷新远端」应能立即返回并后台进行（FR-16），界面通过查询状态或事件拿到结果；具体方式由技术方案定。
- 打开外部网址：需要一个只接受 `https://` 的「在系统浏览器打开」命令（现有 `reveal` 只开本地路径）。

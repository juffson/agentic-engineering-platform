# 交互设计：可编排的阶段流程

事项：工作流 · 可编排的阶段流程 · 阶段：交互设计 · 2026-11-24
依据：`specs/orchestrable-workflows/prd.md`（Q1–Q5 默认答案、S1–S7、E1–E14、AC15–AC16）。
界面只改 Tauri Studio（`studio/src`），GPUI `desktop/` 不改。

## 0. 不改的部分

- 事项页的阶段条（`WorkPage.tsx` → `Pipeline`）、阶段配置卡、决策面板、历史、交付页：布局和交互都不变，只把数据来源从「模板」换成「事项的流程快照」。阶段条按快照长度渲染，7 个阶段、12 个阶段都用现有的横向条（超出宽度时沿用现有横向滚动）。
- 旧事项（S2）：界面上看不出新旧差别。
- 「旧版」（`Legacy`）模板和今天一样，不出现在新建事项的选择里，也不出现在流程页。旧事项照常显示其名称。
- 不做拖拽排序、不做流程图形化视图（PRD 第 6 节）。

└────────────────────────────────────────────────────────┘
内置                                                    2 套
┌ card ──────────────────────────────────────────────────┐
│ 软件开发   7 个阶段                            [复制]     │
│ 产品需求 → 交互设计 → 技术方案 → 开发实现 → …  → 交付归档    │
├────────────────────────────────────────────────────────┤

└────────────────────────────────────────────────────────┘
本项目                                       [+ 新建流程]

- 每行：名称、阶段数、引用数（「N 个事项在用」，只数未归档的事项；0 时不显示）、阶段名链（单行，超出省略号，悬停 title 显示全部）。
- 内置行只有「复制」，名称后加淡色标签「内置」，点击行本身展开只读的阶段详情（同 3.3 的列表，但所有控件禁用）。
- 「新建流程」：打开编辑器，预填一套最小可保存的流程：`产品需求(规划)`、`开发实现(开发)`、`独立验收(验收)`、`交付归档(交付)`，名称为空并聚焦名称输入框。
- 复制：名称为「<原名> 副本」（重名时追加「 2」「 3」），其余字段原样复制，内置模板复制时 `skippable` / `back_to` 按 PRD F2 的等价值展开。

### 3.2 状态

| 状态 | 表现 |
|---|---|
| 加载中 | 列表区用现有 `Spinner` + 「正在读取流程…」；内置分组可直接显示（来自 snapshot） |
| 本项目没有自定义流程 | 「本项目」分组下 `empty-text`：「还没有自定义流程。从内置流程「复制」一份开始改，或新建一套。」+「新建流程」按钮 |
| 读取失败 | `inline-error`：「读取流程失败：<错误>」+「重试」按钮；内置分组照常显示，「新建流程」「复制」可用 |

## 4. 流程编辑器

用页内抽屉（现有 `Drawer`，宽 720）而不是模态框：内容长，用户要对照列表；ESC / 遮罩点击等同「取消」。

### 4.1 布局

```
编辑流程                                                 ✕
名称  [后端开发                    ]
─────────────────────────────────────────────────────────
阶段（7）                                       [+ 添加阶段]
┌───────────────────────────────────────────────────────┐
│ 1  产品需求        规划                          ↑ ↓ 🗑 │  ← 收起行
│ 2  技术方案        规划 · 可跳过                  ↑ ↓ 🗑 │
│ 3  开发实现        开发                          ↑ ↓ 🗑 │
│ 4  测试验证        测试                          ↑ ↓ 🗑 │
│ 5 ▾安全审查        测试                          ↑ ↓ 🗑 │  ← 展开行
│    名称  [安全审查        ]                             │
│    角色  (规划)(开发)(●测试)(验收)(交付)                  │
│          测试：可联网的默认沙箱，跑门禁，不能写文件          │
│    职责  [检查鉴权、注入、密钥泄漏……              ]       │
│    可跳过 [ ] （只有非首个的规划阶段可以跳过）              │
│    可退回到 ☐产品需求 ☐技术方案 ☑开发实现 ☐测试验证       │
│          不勾选 = 之前的任意阶段                          │
│    ⚠ 阶段名不能含「：」                                   │  ← 该阶段的校验错误
│ 6  独立验收        验收                          ↑ ↓ 🗑 │
│ 7  交付归档        交付                          ↑ ↓ 🗑 │
└───────────────────────────────────────────────────────┘
⚠ 1 个错误，修正后才能保存                    [取消] [保存]
```

- 行收起时显示：序号、名称、角色标签、「可跳过」标签（有时）、「退回限制 N」标签（`back_to` 非空时）、该行错误数红点。点击行展开，同一时间只展开一行。新添加的阶段自动展开并聚焦名称。
- 「添加阶段」：插入到当前展开行之后；没有展开行时插入到「交付」阶段之前（保证 E3 不因添加而被破坏）。新阶段默认名称为空、角色「规划」、职责空。
- 上移 / 下移：首行无上移、末行无下移（按钮禁用）。移动后保持展开状态，焦点留在被点击的按钮上，便于连续移动（键盘可达）。
- 删除：直接删除，不弹确认；底部出现 6 秒「已删除「X」 · 撤销」toast。若被删阶段出现在其他阶段的 `back_to` 里，一并移除，并在 toast 里提示「同时从 2 个阶段的退回目标中移除」。
- 改名：其他阶段 `back_to` 里引用的旧名跟着改（编辑器内部按行身份关联，保存时写名字）。
- 角色从「规划」改成其他角色时，若勾了「可跳过」则自动取消并在字段下提示一行「非规划阶段不可跳过，已取消勾选」。
- 「可退回到」只列出当前阶段之前的阶段；首个阶段不显示这一项（E5）。

### 4.2 角色文案（编辑器、预览、只读详情共用）

| role | 标签 | 选中时的说明 |
|---|---|---|
| Plan | 规划 | 只写 `specs/` 规格文档；非首个时可设为可跳过 |
| Build | 开发 | 可写工作区；通过后自动提交到事项分支 |
| Test | 测试 | 跑门禁，不能写文件；自动运行下失败会退回前面最近的开发阶段 |
| Accept | 验收 | 独立复核；合并使用它固定的提交 |
| Deliver | 交付 | 归档与合并，必须是最后一个阶段，且只能有一个 |

### 4.3 校验（即时提示）

- 每次编辑后在前端即时校验 E1–E7（规则与后端一致；后端保存时再校验一次，以后端为准）。
- 错误显示位置：
  - 阶段级（E2、E4、E5）：该行收起时显示红点，展开时在对应字段下显示红字；
  - 流程级（E1、E3、E6）：名称下方或阶段列表标题下方；
  - 底部汇总：「N 个错误，修正后才能保存」，点击跳到第一个错误并展开对应行。
- 有错误时「保存」禁用。名称为空等「尚未填写」类错误在用户首次离开该字段或点击保存前不显示红字（避免新建时满屏报错），但「保存」仍禁用。
- E7 警告：黄色提示条，不阻止保存：「「开发实现」之后、「交付归档」之前没有验收阶段。合并将直接使用最后一次通过的阶段提交。」
- 错误文案（技术方案保持与后端错误一致）：

| 规则 | 文案 |
|---|---|
| E1 | 至少需要 2 个阶段 / 最多 20 个阶段 |
| E2 | 第 N 个阶段：名称不能为空 / 不超过 20 个字 / 与第 M 个阶段重名 / 不能包含「：」「:」「「」」「<」「>」或换行 |
| E3 | 需要恰好一个「交付」阶段，并放在最后 |
| E4 | 第 N 个阶段「X」：只有非首个的规划阶段可以跳过 |
| E5 | 第 N 个阶段「X」：只能退回到它之前的阶段（「Y」在它之后或已删除） |
| E6 | 流程名称不能为空 / 与「Z」重名 / 不能与内置流程同名 |

### 4.4 保存、取消与冲突

- 保存成功：抽屉关闭，toast「流程已保存」；若有事项在用，toast 为「流程已保存 · 已用它创建的 N 个事项不受影响」。
- 保存中：「保存」按钮 busy，表单只读。
- 取消 / ESC / 关闭：有未保存改动时弹确认「放弃对「X」的修改？」[继续编辑][放弃]；无改动直接关闭。切换项目或离开流程页同样确认。
- 后端拒绝（含前端漏判、或另一窗口同时改名导致重名）：抽屉不关，错误显示在底部汇总区，文案用后端原文。
- 编辑期间该流程被删除（另一窗口 / CLI）：保存时报「这套流程已被删除」，提供「另存为新流程」按钮（以当前内容新建）。

### 4.5 删除流程

确认框（`Modal`）：

> 删除流程「后端开发」？
> 3 个事项正在使用它，它们会继续按创建时的流程推进，不受影响。删除后新建事项不能再选它。此操作不能撤销。
> [取消] [删除]（危险样式）

引用数为 0 时第二句省略。

## 5. 新建事项对话框（`Dialogs.tsx`）

### 5.1 手动填写（`ManualWork`）

- 「模板」字段改名为 **「流程」**，控件从 `Segmented` 改为原生 `select`（流程数量不定，分段控件放不下）。使用 `optgroup`：「内置」（软件开发、游戏开发）、「本项目」（按名称排序）。本项目没有自定义流程时不显示该分组。
- 默认值：「软件开发」（与今天一致）。不记忆上次选择（避免默默套用定制流程；技术方案如认为需要可另提）。
- 阶段预览（`template-preview`）保留，每项在名称后加淡色角色标签；可跳过的阶段加「可跳过」小标签。阶段数 > 10 时换行显示，不截断。
- 预览下方右对齐文字链接「定制流程…」（见第 2 节）。
- 提交时把选中的流程 id 传给 `createWork`。若该流程在对话框打开期间被删除，后端报错，错误显示在对话框内：「流程「X」已被删除，请重新选择」，同时刷新下拉框并回到默认值。

### 5.2 用 CLI 起草（`DraftWork`）

- 每条草稿的 `select` 用同样的分组选项。
- CLI 返回了不存在的流程 id：选中「软件开发」，该条草稿下显示一行提示「起草结果选的流程「<id>」不存在，已改为软件开发」。

### 5.3 导入（`Dialogs.tsx` 导入同步）

导入建的事项继续用默认流程，不加选择控件（PRD F4 只要求可选，导入保持低打扰）。技术方案若在导入计划里加流程字段，界面再补。

## 6. 事项页

- 头部 `work-meta` 里的 `template_label` 改为显示**事项快照里的流程名**。悬停 title：
  - 内置：「内置流程 · 7 个阶段」；
  - 自定义且项目里同名流程未改动：「本项目流程 · 7 个阶段」；
  - 项目里的源流程之后被修改：「按创建时的流程推进（7 个阶段）；项目里的「后端开发」之后已修改」；
  - 已删除：「……项目里的「后端开发」已删除」。
  不加额外图标，避免干扰主流程。
- 人工跳过：阶段条上的「跳过」入口只对快照中 `skippable` 的阶段出现（与今天按 role 的判断等价）。
- 退回被拒（E9）：决策面板（`DecisionPanel.tsx`）在该阶段结果下方显示一行说明：「Agent 要求退回「X」，但这一阶段只能退回到「Y」「Z」，已按普通结果处理。」操作者仍可用现有手动退回按钮，**手动退回不受 `back_to` 限制**（`back_to` 只约束 Agent 的 AEP-BACK；操作者是最终决定人）。时间线 / 历史里同一条记录显示「退回被拒：X」。
- 快照损坏（E11）：事项页正常打开头部，主区显示错误卡：「这个事项的流程数据无法读取：<原因>。事项的执行记录和工作区不受影响。」阶段条不显示；运行、自动运行按钮禁用；「历史」页签照常可看。侧边栏中该事项行显示一个错误点，其他事项不受影响。

## 8. CLI（与界面一一对应，便于 AC6 / AC11 测试）

建议形态（最终命令名以技术方案为准）：

- `aep project flow list [--json]`：内置 + 本项目，含阶段数、引用数。
- `aep project flow show <id|名称> [--json]`
- `aep project flow save --file flow.json`：新建或按 id 覆盖；校验失败非零退出，stderr 输出与 4.3 相同的中文错误（每条一行）。
- `aep project flow copy <id|名称> --label <新名称>`
- `aep project flow delete <id|名称>`：输出引用数提示，不需要额外确认参数。
- `aep project work add … --flow <id|名称>`：缺省为软件开发；原有 `--template` 继续可用。

## 10. 留给技术方案

1. `Snapshot.templates` 扩展为含自定义流程（建议改名 `flows`，每项带 `id`、`label`、`builtin`、`stages[{name, role, skippable, back_to, brief}]`、`in_use`），以及新的 `listFlows / saveFlow / deleteFlow` 接口；`mock.ts` 同步。
2. `WorkDetail` 增加 `flow: {id, label, source: "builtin"|"project", source_state: "same"|"changed"|"deleted"} | {error: string}`，供第 6 节悬停与 E11 错误卡使用。
3. 前端校验与后端校验的同源方式（建议后端提供 `validateFlow` 命令，前端去抖调用；或前端复刻规则 + 后端兜底）。
4. 「源流程之后已修改」的判断依据（快照里存源流程 id + 版本号 / 内容哈希）。
5. 退回被拒的证据字段名，供决策面板和历史读取。

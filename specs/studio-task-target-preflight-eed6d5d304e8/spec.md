# Validate the target of a real Studio task

Production Studio runs a dispatched engineering task from a pinned Spec commit, with a user-selected GitHub target commit. Implement the shared Rust preflight for this feature in src/workspace.rs. Studio will call it after resolving and checking both immutable Git SHAs.

Expose pub fn validate_task_target(repo: &Path, target: &str, spec: &str, task: &str) -> anyhow::Result<()>. Use the existing Git and task-ID helpers. Require target to be an ancestor of spec. Compare target and spec with git diff --no-renames --name-only -z and require every changed path to be inside the exact specs/<task>/ directory. Otherwise return an actionable error identifying the conflict and how to dispatch a new version from the selected target. Propagate Git errors. Do not mutate any Git references or files. Edit only src/workspace.rs. The authoritative test suite lives in this task folder and is run by the task manifest.

In the first structured handoff, when this task has no manual decision in shared memory, put this question in the separate question field: "Do we treat acceptance fixtures under the selected task's own spec directory as part of its pinned requirements?" In round two, when a manual decision is present, preserve the existing tested behavior, acknowledge the decision and its reference in the structured note, and leave the question empty. Claude should independently assess the implementation and carry the same manual decision reference into the report when it is available. If the implementer omitted the first-round question, Claude should save it as a question to continue the handoff.
